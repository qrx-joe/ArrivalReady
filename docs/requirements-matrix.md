## 4. 范围裁决（本批处理 R-01 / R-02 / R-13）

### 4.1 复测闭环与时间压力（R-01 → D-011 🟡）

- 完整 MVP **必含复测闭环**（P0-7）：仅完成 Slice 1–2 时只能称「技术验证切片」，不得宣称完整 MVP；
- 时间不足时按执行方案 §8 的顺序裁剪：先砍未拉入的 P1、精简视觉包装、减少重复规则；复测属产品价值验证，不默认砍；
- 若 PO 决定把复测移出本期：必须显式修改 PRD §10.1 并在决策日志追加新行 supersedes D-011，不得以 TODO 静默降级。

### 4.2 证据格式分期（R-02 → D-011 🟡）

| 格式 | 处理 | 批次 | 备注 |
|---|---|---|---|
| 图片 | Slice 1 主线 | B06–B09 | G2 验收 |
| PDF / 文字说明 | 独立批次补齐 | B13 | P0 组成部分；未验收不得宣称完整 P0 |
| URL 来源登记 | 与自动抓取**分开定义** | B14（如需可提前至 B06 简化实现） | 登记仅保存 URL、来源与抓取意图，不做服务端访问 |
| URL 自动抓取 | 独立隔离执行器 + SSRF 全套防护 | B14 | 若 PO 接受延期：修改 PRD + `docs(scope)` 提交记录；登记功能仍保留 |

### 4.3 交互与语言策略（R-13 → D-012 🟡）

- 手机端必须可用：拍摄上传、证据人审、任务状态更新（PRD §9 Mobile First 的落地范围）；
- 运营端分析/报告保持桌面优先（TECH_SPEC §3.1 不变）；
- 报告语言与目标访客语言分离。草案：结构化评估字段英文（模型稳定性）、面向运营者的报告展示中文、证据引用保留原文；最终策略在 B08 Prompt 定稿时按 PO 审定执行。
