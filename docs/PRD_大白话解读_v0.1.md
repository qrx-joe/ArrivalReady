# Arrival Ready PRD 大白话解读

> 本文是 [01_ArrivalReady_PRD_v0.1.md](01_ArrivalReady_PRD_v0.1.md) 的非官方通俗解读，面向非技术读者。
> 与正式 PRD 不一致之处，以正式 PRD 为准。
> 整理日期：2026-09-08

**全文贯穿一个比方：这个产品就是一家"给店铺做体检的医院"**——店家来体检、出体检报告、开治疗方案、跟踪治疗、复查对比。记住这个比方，下面就好懂了。

---

## 开头那段小字（文档封面信息）

- **"PRD"** = 产品需求文档。就是开工前写的"说明书"，讲清楚我们要做个什么东西、给谁用、做到什么程度。免得大家各干各的，做出来不是一回事。
- **"v0.1"** = 第一版草稿，后面肯定还会改。
- **"候选项目，尚未完成需求验证"** = 这句话很重要：**这只是一个点子，还没证明市场上真有人需要它**。文档主动提醒读者：别把这当成板上钉钉的事。
- **"赛道：沪潮涌江…"** = 他们是参加一个上海的比赛（主题是"AI 帮城市品牌走向世界"），这个产品就是为比赛做的。
- **"产品负责人/技术负责人"** = 谁管事儿、谁管写代码，分工名单。

---

## 第 0 章：这份文档是干嘛的

- 这章就说：下面会讲清楚这个点子的"机会在哪、给谁用、有啥用、做到哪、怎么赚钱、怎么运营、看什么数据、有什么风险"。
- **"先验证问题，再自动化解决方案"** = 先确认真的有人需要，再动手写代码。别反过来。
- **"模型只是系统中的一个推理节点，而不是整个产品"** = ChatGPT 这种 AI 只是一个零件，就像体检报告里"看片子的医生"，不是整家医院。整个产品还有挂号、化验、报告、治疗方案、复查一整套流程。
- **"E0–E4 证据阶梯"** = 一套给"点子可信度"打分的方法，像侦探破案：
  - E0 = 纯粹的猜测（"我觉得外国人买东西不方便"）；
  - E1 = 有点旁证（"新闻说上海在搞国际化"）；
  - E2 = 找到真实案例（"上个月有家店真因为老外看不懂菜单丢单了"）；
  - E3 = 对方有实际行动（愿意给资料、愿意配合整改）；
  - E4 = 掏钱（真付费、交定金）。
- **"口头意愿不等于真实需求"** = 你问朋友"如果有这App你会用吗"，他说"会啊"，这不算数。他真的下载了、付钱了，才算数。
- **"option-skill"** = 上面这套方法是从一个开源项目学来的，文档注明了出处。

## 第 1 章：一分钟看懂这个产品

- **一句话介绍** = 帮店家在外宾来之前，检查"找到店→看懂→挑选→动手买→付钱→出事找人帮忙"这一整条链路通不通，发现的问题能变成任务去改，改完还能再测一次。
- **核心命题** = 市面上已经有很多"给外国游客用的 App"（导游、翻译、支付）。我们不跟他们抢，我们**反过来站在店家这边**：游客真的推门进来了，这家店接得住吗？
- **"产品不是"清单** = 主动划清界限，防止别人误会：
  - 不是翻译菜单的工具；
  - 不是 AI 导游；
  - 不是帮店写英文文案的；
  - 不是"让 AI 扮演一个外国人来挑毛病"的聊天框（后面会解释为什么这个不行）；
  - 不是网页测试工具的抄版；
  - 不是"一键生成英文官网"的。

  **为什么特意声明这些？** 因为上面这些事 ChatGPT 都能干，干得还挺好。如果我们的产品只是干这些，那用户没理由用我们。

- **"产品真正交付的结果"** = 体检完成后，店家拿到手里的 9 样东西，对着医院比方看：
  1. **Readiness Score（准备度分数）** = 体检分项得分，不是含糊的"你身体还行"；
  2. **Findings（问题清单）** = 查出的具体毛病，比如"血管堵了30%"，不是"你亚健康"；
  3. **Evidence（证据）** = 每个毛病都附化验单、片子，不是医生拍脑袋说你生病了；
  4. **Severity（严重程度）** = 这病是要命的还是小毛病；
  5. **Fix Plan（整改方案）** = 怎么治，具体可执行；
  6. **Owner & Status（负责人和进度）** = 谁负责治，治到哪一步了；
  7. **Retest（复查）** = 疗程结束后再查一次，看好没好；
  8. **History（历史档案）** = 历次体检结果都留着，能对比；
  9. **Guest Layer（应急页）**（可选）= 如果店一时半会改不好，先做个"外国人看得懂的临时网页+二维码"贴在店里顶着，像先贴个创可贴。

## 第 2 章：先承认我们不知道什么

这章是全文最"实诚"的一章。

- **"当前证据等级 E0–E1"** = 按侦探那套标准，这项目现在只到"有猜测+有旁证"的阶段。
- **"当前可以确认的是"** = 我们知道的事实：上海确实在大力度搞外国人服务（这是新闻能查到的）；市面上"验证体验"这类产品确实存在。**但这只能说明大方向不荒唐，不能说明我们这个具体产品有人要。**
- **"当前尚未确认的是"** = 一连串要命的问题全都没答案：店家真的因为这个亏过钱吗？最痛的是小老板还是连锁总部？他们现在怎么凑合的？花过钱吗？愿意配合改吗？谁管掏钱？——这些都要靠去问真人才能知道。
- **"E2 痛点句式"** = 一个填空题模板："【某类店家】在【外国客人来消费时】想【让他顺利完成】，但因为【只按本地人设计】，产生了【具体损失】。" 注意：目标**不是**找店主来点头说"对对对我有这个困扰"（嘴上附和太容易了），而是挖出**真实发生的事**来填这个空。只有"最近的真实事件 + 说得清的损失"才算过关。

## 第 3 章：都有什么人参与

四种角色：

- **U1 门店运营人员（主要用户）** = 真正天天用这个软件的人：上传材料、看问题、派人整改。相当于**陪病人来看病、管着病历本的那个人**。
- **U2 国际访客（受益者）** = 外国游客。**他们根本不会装这个 App**，甚至不知道它的存在，但他们间接受益——店变得更好懂了。就像餐厅后厨改造，食客不知道但吃得更放心。
- **U3 老板/连锁总部（掏钱的人）** = 他们不操作软件，但决定买不买。他们关心的是：这玩意能不能提高营业额、减少投诉、多家店统一标准、花的钱值不值。
- **U4 商圈/文旅管理方（潜在的大客户）** = 比如一条美食街的管理处、文旅局。他们想一次管几十上百家店，统一标准、批量验收、向上级展示成绩。这是可能的大单子。

**注意一个关键点：用的人和掏钱的人往往不是同一个。** 软件要同时伺候好两种人。

---

## 第 4 章：用户到底想完成什么事（JTBD）

JTBD = "Jobs To Be Done"，意思是"用户雇你这个产品来帮他干的活"。分三层：

- **功能上的活** = "我想知道我店里到底哪一步会让外国人卡壳，并且给我能落地的改法"——不是要一份"提升国际化水平的建议"（那种空话网上到处是）。
- **情感上的活** = "我想在客人投诉、扭头就走**之前**就发现问题"，而不是当场手忙脚乱地拿手机翻译、店员连比划带猜。
- **社交上的活（面子上的活）** = 老板要能跟总部/上级证明："我们不是随便贴了张英文菜单应付，我们是做了一套完整、有据可查的整改。"——这话说出去有底气。

---

## 第 5 章：外国客人在店里的完整旅程（7 步）

这是检查标准的骨架。想象一个不懂中文的老外来吃火锅，一步一步走：

1. **Discover 发现** = 他能找到你店吗？地图上名字对不对？营业时间能不能看懂？门朝哪开？
2. **Understand 理解** = 他知道你是卖什么的吗？菜单上"毛肚""鸭血"直译成英文，他知道是什么吗？（有些东西光翻译没用，得解释。）
3. **Decide 决策** = 他能比较着选吗？知道这份菜多大份、多少钱、辣不辣、有没有花生过敏原吗？
4. **Act 行动** = 他能动手吗？扫码点单——结果扫进去一个全中文的小程序，直接卡死。能排队吗？能预约吗？
5. **Pay 支付** = 他知道能刷维萨卡吗？能用现金吗？支付宝外卡绑定流程他搞得定吗？
6. **Recover 求助** = 出错了怎么办？想退菜、退票、投诉，找谁？有没有他看得懂的求助渠道？
7. **Remember 离店延续** = 他记得住你的店名吗？还能再找到你吗？能推荐给朋友吗？

**为什么要看全 7 步？** 因为很多店只在"翻译"上下功夫（第2步），但客人往往死在第4步（全中文小程序）或第5步（不会付款）——前面翻译得再漂亮也没用。这就是"端到端检查"的意义。

## 第 6 章：竞争对手分析

- **"竞争不是只看长得像我们的产品"** = 你的对手不只是同类产品，还包括"用户现在的一切替代办法"，包括"什么都不干、凑合着"。
- 六类对手逐个说：

  1. **通用大模型（ChatGPT 等）**：什么都能干一点。重叠度很高，所以我们必须有它们没有的：标准、证据、任务闭环、历史记录。
  2. **翻译/本地化公司（Phrase、Lokalise）**：帮企业管多语言内容。它们管"文字"，我们管"整条线下流程"，比它们管得宽。
  3. **AI 模拟用户测试（PersonaQA 等）**：让 AI 扮演用户去逛网页、报告哪里卡。**和我们重叠最大的对手**。我们的差异：它们测网页，我们还能测线下实体空间、支付、店内流程。
  4. **真人测试公司（Applause）**：花钱雇真外国人去实测，质量高但死贵。我们的差异：便宜得多，先用 AI 筛一遍，需要时再升级真人。
  5. **上海本地游客服务平台（Meet China、沪小游）**：服务游客的官方 App。它们服务游客，我们服务店家，不打架。
  6. **店里的土办法（店员拿手机翻译、贴英文菜单、找会英语的朋友帮忙）**：这是最隐蔽也最大的"对手"——免费、马上能用。我们必须比土办法强在：把问题**记下来、结构化、能重复做、能复查**，土办法是散的、做完就忘。

- **关键竞品事实** = "AI 扮演外国游客"这件事别人已经做出来了，不新鲜了，**绝对不能拿它当卖点**。

---

## 第 7 章："通用 AI 能替代 80% 就砍掉"测试

这是文档里很狠的一把刀，规则只有一条：**如果用户把同样的材料发给 ChatGPT 聊天就能解决 80%，这功能就不配当我们产品的核心。**

然后逐个功能过堂：

| 功能 | 大白话结论 |
|---|---|
| 翻译菜单 | ChatGPT 干得比我们好（90%+能替代），**放弃** |
| 解释文化概念 | 大部分能被替代，只当个零件 |
| 看照片给建议 | 大部分能被替代，**放弃** |
| 生成英文页面 | 大部分能被替代，只能当赠品 |
| 带证据的标准化验收 | ChatGPT 只能干一小半 → **核心** |
| 问题分类+确定性算分 | 干不了 → **核心** |
| 任务分配/进度跟踪 | 几乎干不了 → **核心** |
| 复测+前后对比 | 几乎干不了 → **核心** |
| 多店横向对比 | 需要积累数据后才有，**长期壁垒** |
| 真实整改效果数据 | 同上，**长期壁垒** |

- **产品原则总结** = "模型可以随时换掉；标准、证据、流程、历史记录、真实效果数据不会跟着模型消失。" 意思是：ChatGPT 明年可能被别家取代，没关系，我们的价值不在模型上。

## 第 8 章：价值主张（用了到底有啥不一样）

- **对单店**：以前老板的心声是"我大概弄了英文版，应该行吧？"（心里没底）。用了之后变成："我知道第几步会失败、为什么失败、证据是什么、谁去改、改完过没过。"（心里有数。）
- **对连锁/商圈**：从各家店各管各的、靠人巡逻，变成一套标准、一套问题分类、能量化打分、能批量整改、能追踪复查。
- **对游客**：少遇到"每个单词都翻译对了，但流程还是走不下去"的憋屈。

## 第 9 章：产品十诫（十条原则）

逐条翻译：

1. **证据优先** = 每个重要结论必须带上证据，不带证据的等于没说；
2. **分数由程序算** = AI 不许张嘴就来"你这店83分"；
3. **AI 提建议，人拍板** = 关键结论必须人工确认后才算数；
4. **报告不是终点** = 出了报告问题没改，等于白干；改完复测通过才是终点；
5. **模型可换** = 今天用 A 家 AI，明天能换 B 家，不被绑死；
6. **不许装确定** = AI 没把握的事必须明说"我不确定"，不许不懂装懂；
7. **手机优先** = 店员是拿手机在店里干活，不是坐办公室用电脑；
8. **少碰个人隐私** = 能不收集个人信息就不收集；
9. **先人工后自动化** = 先用笨办法跑通，再自动化，别一上来造大机器；
10. **管住手** = MVP 阶段不做 CRM、不做支付、不做旅游平台，忍住。

## 第 10 章：MVP 范围（第一版做什么）

**MVP** = "最小可行产品"，就是**最小能用的第一版**——先把最核心的闭环跑通，别的以后再说。

优先级分四档：**P0 必须有 / P1 强烈想要 / P2 比赛后再说 / 明确不做**。

### P0（七个必做功能）

1. **P0-1 创建验收项目** = 给店建档：店名、类型、地址、接待哪国客人、这次查哪些方面；
2. **P0-2 上传证据** = 传照片、PDF、网址链接、文字说明（第一版可以不支持视频）。系统要记住每个证据"从哪来、什么时候传的、对应旅程哪一步"；
3. **P0-3 自动分析** = AI 检查后输出**结构化的问题**（就是格式固定的一张表）：哪个规则违反了、问题类型、发生在旅程第几步、多严重、标题、描述、证据编号、把握多大、建议怎么改；
4. **P0-4 验收报告** = 界面上能看到：各维度得分、通过/警告/不通过、严重问题、证据、整改建议；
5. **P0-5 人工确认** = 人可以对 AI 的每条结论：确认 / 驳回 / 修改 / 标"不适用" / 写备注；
6. **P0-6 整改进度** = 每个问题有状态条：发现 → 已认领 → 整改中 → 待复测 → 已解决（或"已知风险，不改了"）；
7. **P0-7 复测** = 改完后再来一轮新检查，**旧结果原封不动保留**，能做前后对比。

### P1（强烈想要，第一版最好有）

给老外的应急页面、二维码、自动检查网址、团队成员分工、导出报告、英/日文两种访客档案、简单数据统计、显示"这次检查用的是哪个版本的规则和 AI"。

### P2（比赛后再说）

视频证据、多门店管理、行业对比、真人复核市场、自动监测网页变化、连锁模板、对外开放接口、权限管理、商圈批量任务、真实营业数据回传。——都是锦上添花。

### 明确不做（Won't Have）

支付系统、订酒店机票、完整客户管理、社交社区、100种语言、改别人家的小程序、"AI官方认证"的金字招牌（没有权威背书就不能装权威）、未经同意收集游客数据。

**为什么专门列一页"不做"？** 因为做产品最大的死法不是"做得太少"，是"什么都想做"然后烂尾。提前白纸黑字写下不做，才挡得住中途加需求的手。

## 第 11 章：IRRS 检查标准 v0.1

**IRRS** = 自研的一套"国际访客接待准备度标准"。相当于医院自己编的体检项目表。

- **重要声明**：这是自家内部标准，**不许对外吹成"政府认证"或"行业标准"**——没那个资质，吹了是欺骗。

- **7 个检查维度和权重**（总 100%）：

  | 维度 | 权重 | 大白话 |
  |---|---:|---|
  | 能被找到 | 10% | 老外找得到这家店吗 |
  | 能看懂 | 20% | 看不懂后面全白搭，所以权重高 |
  | 能做决策 | 15% | 能比价、知道份量过敏原吗 |
  | 能完成操作 | 20% | 点单预约购票走得通吗，权重高 |
  | 能付钱 | 15% | 外卡现金移动支付都明示了吗 |
  | 出事能求助 | 10% | 退款投诉有渠道吗 |
  | 文化语境/后续 | 10% | 离店后还能想起你吗 |

  （注明：这些权重是拍脑袋的初版假设，没经过实践验证，以后会改，改了要记版本号。）

- **严重程度 5 档**：
  - S0 阻断 = 根本没法完成（扫码进不去点单系统）；
  - S1 严重 = 大概率把客人气走；
  - S2 较大 = 明显费劲、得店员帮忙；
  - S3 轻微 = 别扭但能完成；
  - 信息 = 纯建议，不扣分。

- **算分规矩**（这段是重点）：
  1. AI 只判断每个检查项"过/不过"；
  2. 人可以复核；
  3. 总分由**程序**按权重算出来；
  4. 每次检查记录用的是哪一版标准；
  5. 标准以后改版了，**不许回头改历史分数**——不然前后对比就没意义了。

---

## 第 12 章：三个核心流程 + 一个"哇"时刻

- **流程 A 首次验收** = 建档 → 选目标客人 → 传证据 → AI 预处理 → AI+规则检查 → 出问题和证据 → 人确认 → 出报告。（第一次体检的完整流程。）
- **流程 B 整改** = 点开一个严重问题 → 看证据 → 看建议改法 → 指派负责人 → 去改 → 标记"改好了，可以复测了"。（开药治病。）
- **流程 C 复测** = 重新收证据 → 跑一次全新的检查 → 新结果和旧结果对比 → 哪些解决了、哪些还犯着。（复查。注意：是**全新一次检查**，不是在旧结果上打勾——防止糊弄。）
- **Magic Moment（哇时刻）** = 设计产品时刻意打造的一个瞬间：**用户亲眼看到"系统不光说有问题，还指着证据告诉你为什么，而且改完之后亲眼看到 FAIL 变成 PASS"**。文档强调：这个瞬间的冲击力比"AI 写了一段漂亮的建议"重要一百倍。这是用户决定"这玩意真有用"的那一刻。

---

## 第 13 章：页面清单

就是软件有哪些页面：首页、项目列表、新建项目、项目详情（总览/证据/检查记录/问题/任务）、某次检查的详情（分数/旅程图/问题/对比）、某个问题的详情（证据/规则/AI解释/人工审核/整改/复测）、设置。还有 P1 的"给老外看的页面"（这个店是什么/能干什么/怎么点单/怎么付钱/注意事项/怎么求助）。

注意最后一句：**Guest Page 只是整改手段之一，不是产品本体**——它是创可贴，不是器官移植。

---

## 第 14 章：用户故事（User Stories）

**"用户故事"** = 一种写需求的格式："作为【某种人】，我希望【做某事】，以便【达到某目的】。"每个故事后面跟"验收标准" = 怎样才算做合格了。四个故事：

- **US-01 建项目**：验收标准 = 该填的必须填、每个项目有唯一编号、记录谁建的什么时候建的、能归档但**历史检查记录不许物理删除**（防止毁尸灭迹）。
- **US-02 传证据**：验收标准 = 只接受指定格式、限制大小、显示上传进度、失败能重试、链接要安全（防止直接暴露文件地址）、每个证据能追溯到原始来源。
- **US-03 看问题**：核心就一句——**每条问题必须至少挂一条证据，挂不出证据的必须标注"证据不足"**，同时显示 AI 的把握程度、用的哪条规则、哪版标准，人可以驳回。
- **US-04 复测**：验收标准 = 复测生成全新记录、旧的不许覆盖、能对比、问题可以标记"已解决"或"又犯了"。

---

## 第 15 章：AI 的职责边界

- **AI 负责干的活**：认图片上的字（OCR）、把资料整理成结构、抽取关键信息（比如"这是菜单、这是价目表"）、按规则找问题、给证据写摘要、解释文化差异、起草整改建议、起草多语言页面内容。——都是"跑腿和出主意"的活。

- **AI 不许干的活**：
  - 不许自己定总分；
  - 不许没有证据就断言"这里合法/不合法""这个含过敏原""能刷外卡"；
  - 不许自动发布高风险内容；
  - 不许盖过人的判断；
  - **"AI 自信"不等于"AI 正确"**——模型说话再流利也可能是瞎编的，不能把"它语气很肯定"当成"它说的是真的"。

- **"结构化输出"** = AI 的回答必须是填好的固定格式表格（JSON，一种机器能可靠读取的数据格式），**不许是一大段自由发挥的文字**。因为程序没法可靠地从一段散文里抠数据，今天抠对明天可能就抠错。

- **必须人工确认的高危清单**：支付能不能用、过敏原/食品安全、法规合规、无障碍安全、营业/退款政策、涉及品牌承诺的说法。这些事 AI 说错了会出大事，所以必须人点头。

---

## 第 16 章：给 AI 出考卷（Eval）

AI 会被换版本、改提示词，怎么保证越改越好而不是越改越糟？**考试。**

- **Golden Dataset（标准考卷）** = 先人工出至少 20 道题：8 道明确该判"不及格"的、5 道"警告"、5 道"通过"、2 道"证据不足该说不知道的"。每道题写清：给的什么材料、应该触发哪条规则、应该判什么、严重程度的合理范围、必须引用哪个证据、**不许说出的错误结论**。

- **考试成绩指标**（大白话翻译）：
  - 查出的准确性 = 报的问题里多少是真问题（别狼来了）；
  - 大问题漏报率 = 致命问题有没有漏掉（漏了最要命）；
  - 证据挂钩率 = 结论是不是都有证据撑着；
  - 瞎说率 = 没依据的断言占多少；
  - 格式正确率 = 输出的表格合不合规；
  - 稳定性 = 同样的题跑两遍结果一不一样；
  - 每次检查花多少钱、多快出结果。

- **发布门禁** = 每次想改提示词/换模型/改规则，必须：先考一遍 → 跟上一版比 → 大问题漏报不许变多 → 瞎说率不许超过红线 → 不过就**不许上线**。跟药品改配方要重做临床试验一个道理。

---

## 第 17 章：护城河（别人为什么抄不走）

- **从弱到强排了个序**：AI 模型最弱（谁都能花钱买同样的模型）→ 提示词 → 工作流程 → 规则库 → 跨文化问题分类法 → 整改方案库 → 人工确认过的证据 → 历史记录 → 行业对比数据 → **真实整改效果数据最强**（只有你服务过那么多店才有，别人拿钱都买不到）。

- **一条警惕**："未来可能积累的数据"**不是**现在的壁垒。没发生的不能当已经发生的吹。

---

## 第 18 章：看什么数字（Metrics）

- **北极星指标** = 一个产品阶段只盯一个最重要的数字，像北极星给船指方向。这里的北极星是：**"每个活跃项目里，真正被确认解决的严重问题数"**。为什么不是"生成了多少份报告"？因为报告是纸，问题真解决了才是价值。体检报告印了一万份但没人治病，医院照样是失败的。

- **激活类** = 用户是不是真的开始用了（建了项目、传了证据、跑完第一次检查、确认了第一条问题）；
- **价值类** = AI 的问题被人认可的比例、解决了多少、复测通过率、用多久拿到第一条有用的发现、"用户说'这问题我以前根本没意识到'"的比例（这个很妙——发现盲区最有价值）；
- **商业类** = 试点转付费、平均每店整改多少项、开第二家店、续费、服务毛利；
- **护栏类** = 误报率、瞎说率、隐私事故（必须是0）、检查失败率、单次成本。——护栏指标是"不许变坏"的底线数字。

---

## 第 19 章：怎么赚钱（全是假设！）

文档特意标注：**以下是猜的，不是验证过的定价。**

- **对单店**：三种收费想象——单次体检收费 / 整改服务打包收费 / 持续监测包月；
- **对连锁/商圈**：按店数或按项目周期收，标准模板+批量验收+大屏看板，"服务+软件"混着卖；
- **早期最合理的形态：Service-led SaaS（服务带软件）** = 先用人力手把手帮客户做验收整改（像裁缝铺），把重复的步骤记下来，**只有重复且稳定的部分才做成软件自动化**。好处：避免把错误的想象浇进水泥里（盖成软件就难改了）。

---

## 第 20 章：怎么运营

- **获客**：别烧钱投广告。从比赛合作的商户、认识的上海真实店铺、老字号、文创空间、商圈管理方、朋友能介绍的小店下手——反正现在最重要的是找到真人问，不是冲量。
- **上手门槛**：目标 10 分钟让新用户建起第一个能分析的项目。**不要**一上来就要求企业认证、填20项资料、建组织架构——把人吓跑就完了。
- **AI 日常维护**：每周/每版本固定做：看 AI 这次错在哪、给错误分类、把错题加进考卷、改规则和提示词、重新考试、记录发布版本。——像老师整理错题本。

---

## 第 21 章：用户验证计划（比写代码优先级更高）

- **访谈三不问**（问了等于白问，人只会顺着你说）：
  - "你觉得这产品好不好？"（对方出于礼貌一定说好）；
  - "如果有你会不会用？"（说会用和真用是两码事）；
  - "AI 国际化是不是趋势？"（跟他没关系，他答的不是自己的事）。

- **该问的十件事** = 全是挖真实经历的：上一次接待不会中文的客人是什么时候？他要干什么？第一步发生了什么？卡在哪？店员怎么救场的？花了多久？最后买没买？你后来改过什么？为这事花过钱吗？再发生一次你打算怎么办？——**问过去的事实，不问未来的意愿。**

- **48 小时最小验证** = 找 3-5 家真实店铺（1家餐饮、1家咖啡/零售、1个文化展览空间，最好再找1-2个真外国游客），**人工**给一家店做一次完整体检，然后观察店主的真实反应：认不认这些问题？愿不愿意多给资料？愿不愿意真去改？愿不愿意让我们复查？有没有主动问价格？愿不愿意介绍别的店？——全是行为信号，不是嘴上信号。

---

## 第 22 章：继续的条件和收手的条件

- **绿灯条件（可以继续投入）**：
  - 到 E2：至少 3 家店能讲出具体近期事件+失败环节+实际损失；
  - 到 E3：出现实际行动（花过钱处理过/愿意给资料/愿意被检查/愿意整改复测/主动帮推荐）；
  - 到 E4：出现金钱信号（真付费、定金、采购意向、反复续用、转介绍）。

- **红灯条件（满足任意一条就该停或掉头）**，逐条翻译：
  1. 问了5-8家店，全都讲不出一件具体的失败事件 → 痛可能是想象出来的；
  2. 有问题但店主觉得无所谓、也不想改 → 痛不够深；
  3. ChatGPT加一张提示词就能干80%，而且用户不在乎历史和流程 → 我们没有存在价值；
  4. 找不到能触达的掏钱人 → 有需求也卖不出去；
  5. 必须依赖我们拿不到的数据或系统权限 → 做不了；
  6. AI 检查出来一堆误报且没法改善 → 用户会被狼来了耗死；
  7. 客户只愿意为人工咨询付费、不愿为软件付费 → 那就老实做咨询公司，别硬撑着做软件。

  最后这条特别成熟：**承认"做服务业"也是一种体面的活路，不是失败。**

---

## 第 23 章：风险清单

每行都是"怕什么 + 多怕 + 怎么办"：

- **怕痛点是想象出来的**（极高风险）→ 靠访谈+止损线兜底；
- **怕 ChatGPT 直接平替**（高）→ 把宝押在证据/流程/复测上；
- **怕竞品从网页测试扩张到线下**（中高）→ 靠线下证据+小店场景+本地标准防守；
- **怕 AI 瞎编**（高）→ 强制挂证据+规则引擎+人工审核三道锁；
- **怕上传的材料里有个人信息**（高）→ 少收集、能打码就打码、定期删；
- **怕自动访问网址引来黑客攻击风险（SSRF，一种让服务器乱访问内部网络的攻击手法）**（高）→ 网络隔离+网址白名单+校验；
- **怕功能越做越多做崩**（高）→ 严格分级P0/P1/P2，先做通一家店；
- **怕分数被误会成官方认证**（中高）→ 反复声明是内部标准；
- **怕一开始就接好几家AI供应商把系统搞复杂**（中）→ 先只用一家主力，留个可换的接口。

---

## 第 24 章：路线图（四个阶段）

1. **阶段0 探索期（现在）**：访谈3-5家店、人工做1次体检、验证E2，然后决定"继续/转向/放弃"；
2. **阶段1 比赛MVP**：把建档→传证据→检查→问题→人审→复测→前后对比的最小闭环做出来（**这就是现在代码库正在干的事**）；
3. **阶段2 试点**：找真实商户用起来、加上应急页面、任务协作、真实整改、记录真实结果；
4. **阶段3 多店扩张**：多门店、组织权限、模板、行业对比、开放接口。

---

## 第 25 章：90 秒比赛演示脚本

就是上台怎么演：先一句话点破痛点（"能翻译文字≠能完成消费"）→ 打开一家真实店的项目 → 展示传的门头/菜单/二维码 → 点"开始检查" → 旅程图上跳出2-3个红叉 → 点开一个红叉，亮出证据+规则+改法 → 展示改完后重新提交的证据 → 点"复测" → **红叉变绿（FAIL→PASS）** → 前后对比收尾。结束语："我们不是再做外国游客助手，我们帮城市里的店，准备好接住他们。"

---

## 第 26 章：什么叫"成功"

比赛阶段的成功**不是**"功能做多"，而是六条：有一个真能打开用的 MVP、跑通至少一次完整的"检查→整改→复测"、每条问题带证据、有一个真实商户案例、至少一条 E2 级的真实事件证据、初步证明"ChatGPT 只能替代其中的推理部分，替代不了整个工作流"。

---

## 第 27、28 章：参考资料和文档的规矩

- 27 章就是列了 9 个参考来源（方法论出处、竞品官网、上海官方新闻、网页无障碍标准、API 安全清单），附了链接和查证日期——**结论都要有出处**。
- 28 章是给"这份文档自己"定的规矩，防止文档腐烂：
  - 说"用户很痛""愿意付费"必须注明证据来源；
  - **不许把猜测偷偷写成事实**；
  - 每次访谈后更新证据日志；
  - 每次改范围记录决策日志；
  - 删 P0 需求必须说明原因；
  - 规则改动必须记版本号；
  - 最后一条最狠：**比赛后如果证据没过关，不许因为"代码都写了"就舍不得停。**——沉没成本不是继续烧钱的理由。

## 最后用三句话总结全文

1. **做什么**：给店做"外宾接待体检"——查问题必须带证据、人确认、程序算分、改完复测、前后可对比；AI 只当"会看片子的医生"，不当院长。
2. **凭什么**：翻译和给建议 ChatGPT 就能干，我们不碰；我们卖的是 ChatGPT 给不了的——标准、证据、任务闭环、历史、复查。
3. **什么心态**：全文反复自我敲打——需求还没被验证、所有商业假设都是猜的、先访谈后写码、写了码发现没人要也要敢停。这份 PRD 不光在描述一个产品，还在防备造产品的人自己骗自己。
