# ADR-0002：确定性评分与人审语义（v1 草案）

- 状态：**已接受（2026-09-07 PO 确认，D-018；B10 依此实现）**
- 日期：2026-09-07
- 决策人：AI 起草；审定后状态改为已接受并登记决策日志（supersedes 机制）
- 关闭问题：[文档审查记录 R-04](../04_DOCUMENT_REVIEW_2026-09-07.md)（评分语义未定，不同实现可算出不同分数）
- 关联：PRD §11.3（评分原则）、TECH_SPEC §2.3/§7.7（确定性内核）、执行方案 §5.1（建议草案来源）

## 1. 背景与问题

PRD §11.3 只约定「LLM 不直接打分、按 rule weights 确定性计算、run 绑定 standard_version」，但 WARN 折算、N/A、Reject、Info、覆盖率、零分母、Critical 门槛均未定义。不先固定这些语义，Go 评分服务（B10）无法通过「手算样例一致」验收。

## 2. 决策（建议值，审定前不实现）

### 2.1 输入与分母

1. 每个 AuditRun 创建时冻结「**适用检查项全集**」为分母来源：候选规则先按 `applicability`（entity_types、target_locales、evidence_requirements）做确定性筛选，筛选结果与每项的稳定 key（rule code）在 run 输入快照中记录；后续不得悄悄缩小范围。
2. 同一检查项多个 Evidence / 多条候选 Finding 只计一次——按稳定 key 去重后聚合。
3. `draft` 状态的规则不得进入适用全集；`Info` 严重度规则不扣分也**不进入计分分母**（单独列为建议清单）。

### 2.2 状态折算

| 状态 | 数值 | 说明 |
|---|---|---|
| PASS | 1 | |
| WARN | 0.5 | 部分可达/部分可用 |
| FAIL | 0 | |
| UNKNOWN | 不进入已评估分数 | 缺证据或无法判断；既不奖励也不惩罚 |
| 未审核项 | 不进入已评估分数 | review_required 且尚无人工处置的项 |
| N/A | 从适用全集排除 | **仅限人审给出理由后**；与 UNKNOWN 是不同决策 |
| Reject | 不自动转 PASS | 认可=维持候选状态值；不认可且无替代判断=保留 UNKNOWN |

### 2.3 公式

- 维度分：`100 × Σ(规则权重 × 状态值) / Σ(已评估规则权重)`，仅对该维度**已评估**的适用项求和。
- 维度覆盖率：`已评估适用权重 / 全部适用权重`；同时展示条目覆盖数（n/M）。
- 总分：`Σ(维度分 × 维度权重) / Σ(参评维度权重)`，维度权重取 run 冻结的标准版本定义（PRD §11.1）。
- **发布条件**：仅当所有适用计分项已审定且不含 UNKNOWN 时发布最终总分；否则展示维度分与覆盖率，`total_score = null`，报告标注「部分评估」。若产品希望低覆盖率也出总分，须另定阈值并书面接受风险——不默认。
- 整维处理：整维 N/A（人审确认）可排除并重新归一化；整维缺证据**不得**按 N/A 处理（它压低覆盖率，不消失）。全部适用项均为 N/A/UNKNOWN 时无分数——显示无分数，不得给 0 或 100 冒充已验收。

### 2.4 关键规则

1. S0/S1 FAIL 独立列为「阻断/关键问题」清单，任何均分都不能隐藏；严重度不再乘第二次权重。
2. 置信度（confidence）只做人审排序提示，**不参与算分**。
3. 报告冻结：评分算法版本 + 规则包 hash + 维度权重，写入 run；历史报告读取时按冻结值复算演示，不读当前 active 版本（R-03）。
4. 数值精度：内部全程浮点，**仅在最终展示与持久化时**四舍五入到小数点后 2 位（ROUND_HALF_UP）；比较、Diff、回归一律使用未取整值。
5. 评分修复通过「新算法版本 + 新标准版本」发布，不得重算历史；历史更正显式生成新 run/报告。

### 2.5 人审语义（与评分的衔接）

- confirm：接受候选结论（状态值按候选 status 计）；
- edit：保留原始候选字段 + 修订字段 + 理由 + actor + 时间（可追溯、可重放）；评分取修订值；
- na：必须填理由；把该项从适用全集排除（影响分母），这与缺证据（UNKNOWN，留在分母外但压覆盖率）不同；
- reject：候选结论未获认可——要么给人工替代判断（走 edit 语义），要么该项保留 UNKNOWN；**reject 不产生 PASS**；
- finalize 前置条件：所有 review_required 项都有处置（confirm/edit/na/reject→替代或 UNKNOWN）；存在 UNKNOWN 的报告明确标「部分评估」。

## 3. 手算验收例（B10 实现必须与之一致）

设某维度有 3 项，权重分别为 2/1/1：

1. 结果 PASS / WARN / FAIL：
   维度分 = `100 × (2×1 + 1×0.5 + 1×0) / 4 = 62.50`，覆盖率 4/4 = 100%。
2. 将第三项改 UNKNOWN：
   部分分 = `100 × (2 + 0.5) / 3 ≈ 83.33`，覆盖率 3/4 = 75%，`total_score = null`（部分评估）。
   **不得**因 62.50→83.33 宣称「准备度改善」——分母变了。
3. 第三项经人审判定 N/A（附理由）：
   适用权重全集变为 3，结果 = `100 × (2 + 0.5) / 3 ≈ 83.33`，覆盖率 100%，可发布总分。
   这与情形 2 数值巧合相同，但语义不同：N/A 缩小范围，UNKNOWN 是未完成评估。

## 4. 后果

- 审定通过后：B10 按本 ADR 实现 Go 评分服务，手算样例进单元测试；B02 规则 YAML 的 severity/weight 语义按本 ADR 解释。
- 审定前：本 ADR 是草案，任何代码不得实现其中数值；规则包保持 draft。
- 覆盖率门槛（如「覆盖率 ≥ X% 才可出总分」）若产品需要，必须由 PO 在审定时补充，不允许实现后看结果再定。
